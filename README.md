# DietBot

A Streamlit application that turns a person's profile — height, weight, age, sex, sport,
training duration, activity level and goal — into a daily calorie target, macronutrient
targets, and a meal plan assembled from a nutrition dataset. Generated plans can be saved
to PostgreSQL and read back later.

## The model, and how it was chosen

The original model was a `RandomForestRegressor` predicting macronutrient grams from
height, weight and calories. Inspecting its training data showed why it could not work:
across all 99 rows, every macro target was a fixed multiple of the calorie column.

| macro | grams per calorie | std | correlation with calories |
|---|---|---|---|
| protein | 0.060974 | 0.000141 | 0.999940 |
| carbs | 0.133316 | 0.000134 | 0.999988 |
| fat | 0.028419 | 0.000125 | 0.999769 |

A standard deviation in the fourth decimal place means those labels were generated by a
formula, not observed. The forest could only rediscover the formula — and being tree-based
it could not extrapolate, so **every input above its 2,953 kcal training ceiling produced
byte-identical output**, which covered essentially the entire athlete range the app targets.

### Four designs were tested on real data

The synthetic dataset was replaced with **NHANES 2017–2018** (US CDC / NCHS, public domain):
4,624 adults with measured height, weight, age, sex and a 24-hour dietary recall. Four model
designs were then evaluated against baselines:

| Design | RandomForest R² | Baseline | Kept? |
|---|---|---|---|
| Macro grams from body + calories | 0.571 | **0.582** — calories × a fixed ratio | No — loses to a one-line formula |
| Macro grams from body alone | 0.033 | −0.004 — predict the mean | No — beats the mean, but no useful power |
| Macro composition (% of energy) | **−0.054** | −0.013 — predict the mean | No — worse than predicting the mean |
| **Calorie intake from body** | **0.130** | 0.071 — Mifflin-St Jeor | **Yes** |

Reproduce the three rejected designs yourself:

```bash
python scripts/train_models.py --rejected
```

The conclusion is about the relationship, not the dataset: once a person's calorie intake is
known, their macro grams follow the population ratio closely, and body measurements explain
almost none of what remains. **Macro targets are therefore computed directly**
(`src/macro_targets.py`) rather than predicted, and the RandomForest does the one job it
measurably does better than the formula it replaces.

### The shipped model

`RandomForestRegressor` predicting daily calorie intake from age, sex, height, weight and BMI.
Trained with a 60/20/20 split (2,774 / 925 / 925); `min_samples_leaf` chosen on the validation
split only, with the test split used once.

| Model | MAE (kcal) | R² |
|---|---|---|
| mean baseline | 684.4 | −0.001 |
| Mifflin-St Jeor (the formula the app already used) | 650.6 | 0.071 |
| **RandomForest** | **632.9** | **0.130** |

Feature importance is dominated by sex (0.61), then age (0.22) and height (0.14).
These figures are written to `models/model_metrics.json` by the training script and asserted
in the test suite, so a retrain that stopped beating the baseline would fail CI rather than
leave this README quietly wrong.

### What the model predicts — and what it does not

It predicts **what people with a similar profile were recorded eating**. That is a
descriptive question, and a different one from what any individual *should* eat. The app
displays it as a reference figure and **builds the meal plan from the Mifflin-St Jeor target,
not from the model**.

---

## Honest limitations

- **R² of 0.130 is low.** A single 24-hour dietary recall is a noisy measure of habitual
  intake — the test set's own standard deviation is about 855 kcal — so most of that variance
  is not predictable from body measurements by any model. The honest claim is narrow: it is
  modestly better than the standard formula at this task.
- The model predicts **typical intake, not requirement**, and self-reported intake is known
  to be under-reported. It reads lower than the formula target, consistently.
- **This is not medical advice** and makes no clinical claim. It is a planning aid.
- The macro split is fixed and does not vary by sport or goal — the data did not support
  varying it. Goal changes the calorie target, and macros scale with it.
- The food dataset has **145 items**, mostly South Asian dishes, so coverage is narrow.
- Meal plans use a greedy nearest-neighbour search, not a true optimiser, so they approach
  the macro targets rather than hitting them exactly.
- No allergy, dietary-restriction or meal-timing support.

## Architecture

```
Profile input (Streamlit sidebar)
        │
        ├─► calculations.py ──► BMI, BMR, TDEE, session burn      (standard formulas)
        │                            │
        │                            ▼
        │                     Daily calorie target
        │                            │
        ├─► calorie_predictor.py ──► typical intake estimate       (RandomForest, NHANES)
        │                            (shown as reference only)
        │                            │
        │                            ▼
        ├─► macro_targets.py ──► protein / carbs / fat / sugar     (direct calculation)
        │                            │
        │                            ▼
        ├─► meal_recommender.py ──► meal plans                     (NearestNeighbors, 145 foods)
        │                            │
        │                            ▼
        ├─► storage.py ──────────► PostgreSQL (optional)           (profile + plan + foods)
        │
        └─► ai_explainer.py ─────► plain-language summary (optional, falls back to a template)
```

```
dietbot/
├── app.py                      # Streamlit UI
├── sql/schema.sql              # PostgreSQL schema
├── data/
│   ├── food_data.csv           # 145 foods with nutrient breakdowns
│   ├── nhanes_intake.csv       # built by scripts/build_dataset.py
│   └── macro_targets.xlsx      # the original synthetic dataset, kept for reference
├── models/
│   ├── calorie_intake_rf.pkl
│   ├── nearest_neighbors_model.pkl
│   └── model_metrics.json      # held-out metrics, written at training time
├── src/
│   ├── calculations.py         # BMI, BMR/TDEE, MET burn — no ML
│   ├── calorie_predictor.py    # loads the RandomForest
│   ├── macro_targets.py        # calorie target → macro grams
│   ├── meal_recommender.py     # NearestNeighbors food matching
│   ├── storage.py              # PostgreSQL persistence (psycopg2)
│   └── ai_explainer.py         # optional summary, with fallback
├── scripts/
│   ├── build_dataset.py        # downloads NHANES, writes data/nhanes_intake.csv
│   └── train_models.py         # trains and evaluates; --rejected reproduces the failures
└── tests/
```

**Tech:** Python · Streamlit · scikit-learn · pandas / NumPy · PostgreSQL (psycopg2) ·
pytest · OpenAI API (optional)

## Running it

```bash
git clone https://github.com/Anubhavkumarkanth/Dietbot-An-AI-Powered-Diet-Plans-for-Atheletes.git
cd Dietbot-An-AI-Powered-Diet-Plans-for-Atheletes
pip install -r requirements.txt
streamlit run app.py
```

The app runs with no configuration at all. Both `.env` settings are optional:

```bash
cp .env.example .env
```

| Variable | Required | Effect if unset |
|---|---|---|
| `OPENAI_API_KEY` | No | A templated plan summary is shown instead of a generated one |
| `DIETBOT_DB_URL` | No | Plans are not saved and no history is shown; everything else works |

### Optional: PostgreSQL persistence

```bash
psql -U postgres -c "CREATE ROLE dietbot_app LOGIN PASSWORD '<your-local-password>';" \
                 -c "CREATE DATABASE dietbot OWNER dietbot_app;"
psql -U dietbot_app -d dietbot -f sql/schema.sql
```

Then set in `.env`:

```
DIETBOT_DB_URL=postgresql://dietbot_app:<your-local-password>@localhost:5432/dietbot
```

Three tables: `profiles` → `plans` → `plan_items`, with foreign keys and cascading deletes.
Saving a plan writes to all three in a single transaction, so a half-saved plan cannot exist.

### Rebuilding the data and models

Both artifacts are committed, so this is only needed if you want to reproduce them:

```bash
python scripts/build_dataset.py     # re-downloads NHANES → data/nhanes_intake.csv
python scripts/train_models.py      # retrains, re-evaluates, rewrites model_metrics.json
python scripts/train_models.py --rejected   # reproduces the three rejected designs
```

## Tests

```bash
python -m pytest
```

24 tests. The five persistence tests skip automatically when `DIETBOT_DB_URL` is unset, so
the suite passes without a database.

They cover: model loading; prediction type and plausible range; that predictions actually
respond to their inputs; a regression test against the old model's flatline failure; invalid
input handling; that the recorded metrics still beat the formula baseline; macro targets
reconciling with the calorie target they came from; meal-plan construction; and — with a
database — transactional saves, cascade deletes, and that a constraint violation rolls the
whole save back.
